# 56.0.0-beta.2

Second beta of the Expo SDK 56 line. Packages publish under the npm `beta` dist-tag;
`npm install @terreno/ui` (no tag) still resolves to the stable `0.x` release.

```bash
bun add @terreno/ui@beta @terreno/api@beta @terreno/rtk@beta
# optional local-first data layer
bun add @terreno/syncdb@beta
```

## Upgrade Expo before Terreno

This line targets Expo SDK 56. Upgrade the app first, then install Terreno betas:

| Package | Version |
|---------|---------|
| `expo` | `~56.0.12` |
| `react-native` | `0.85.3` |
| `react` | `19.2.3` |
| `typescript` | `~6.0.3` |

Follow Expo's SDK 56 upgrade guide, then bump `@terreno/*` to `56.0.0-beta.2` (or `@beta`).
Run `bun run compile` / `bun run lint` at the app root and regenerate the OpenAPI SDK after
any `@terreno/api` surface change (`bun run sdk` in the frontend).

Terreno's version major now tracks the Expo SDK major. Stay on the latest `0.x` packages
until you are ready to move the app to Expo 56.

## New package: `@terreno/syncdb`

Optional local-first layer (TinyBase MergeableStore, durable outbox, websocket delta sync,
encrypted web persistence). Install as `@terreno/syncdb@beta` (or the exact version). See:

- [`docs/how-to/migrate-rtk-to-syncdb.md`](https://github.com/TerrenoLabs/terreno/blob/master/docs/how-to/migrate-rtk-to-syncdb.md)
- [`docs/reference/syncdb.md`](https://github.com/TerrenoLabs/terreno/blob/master/docs/reference/syncdb.md)

`@terreno/syncdb` does not replace the generated OpenAPI SDK, Better Auth wiring, or
feature flags — only collection sync/CRUD offline paths.

## `@terreno/rtk` deprecated for data sync

As of **56.0.0**, RTK Query hooks for **collection CRUD** are deprecated. Migrate to
`@terreno/syncdb` using the migration guide above. Keep `@terreno/rtk` for:

- `bun run sdk` / `store/openApiSdk.ts` (non-synced routes)
- Better Auth session Redux (`generateBetterAuthSlice`)
- Feature flags and socket helpers

`@terreno/rtk` remains published through the current major line and will not ship in the
next major release.

### Read hook (before → after)

```typescript
// Before — RTK Query
const {data, isLoading} = useGetTodosQuery({completed: false});

// After — syncdb
const todos = useQuery<Todo>("todos", {filter: (t) => !t.completed});
```

### Write hook (before → after)

```typescript
// Before — RTK Query
const [createTodo, {isLoading}] = usePostTodosMutation();
await createTodo({title, completed: false}).unwrap();

// After — syncdb
const {create} = useMutate("todos");
create({data: {title, completed: false}});
```

## `excludeArchivedPlugin` now filters `findOne`

`excludeArchivedPlugin` applies the same archived filter to `findOne` that it already
applied to `find`, matching `isDeletedPlugin`. Code that relied on `findOne` returning
archived documents must query with an explicit archived override or a different plugin
configuration.

## Sync / REST error codes

Sync and REST CRUD executors preserve kebab-case error `code` values
(`create-not-allowed`, `update-not-allowed`, `delete-not-allowed`, `invalid-request-body`)
and status-specific error names on hook-rejection paths. Clients that matched on older
code strings should update.

## From `56.0.0-beta.0`

`beta.0` was cut from `release-56.0.0`. This beta is cut from `master` after that branch
merged (`#976`), and also includes `@terreno/comms` plus the sync/Mongoose 9 fixes listed
in `CHANGELOG.md` for this version.
