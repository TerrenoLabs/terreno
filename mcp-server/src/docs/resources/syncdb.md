# @terreno/syncdb Documentation

Local-first data layer and request client for Terreno frontends. The on-device TinyBase store is
the UI source of truth for synced collections; every other route goes through the request client
and generated hooks. Since Terreno 58 there is no Redux and no `@terreno/rtk`.

## Key exports

- `@terreno/syncdb`: `createSyncDb`, `betterAuthAdapter`, `bridgeBetterAuthReactClient`, `wipeLocalData`, `listConflicts`
- `@terreno/syncdb/react`: `SyncDbProvider`, `useQuery`, `useEntity`, `useMutate`, `useSyncStatus`, `useConflicts`, `ApiClientProvider`, `useApiQuery`, `useLazyApiQuery`, `useApiMutation`, `useSocketEvent`
- `@terreno/syncdb/api`: `createApiClient` (auth, refresh-on-401, envelope unwrap, cache + tags)
- `@terreno/syncdb/auth`: `createBetterAuthClient`, `SessionProvider`, `useSession`
- `@terreno/syncdb/config`: `baseUrl`, `baseWebsocketsUrl`, `appHeaders`
- `@terreno/syncdb/flags`: `useFeatureFlags`, `useTerrenoFeatureFlags`
- `@terreno/syncdb/app`: `useUpgradeCheck`, `canOpenAdminPage`, `installDevConsoleLogger`, `useMCPTools`
- `@terreno/syncdb/testing`: `createFakeTransport`
- `terreno-syncdb-codegen` (bin): `--out store/syncDbSdk.ts` for collections, `--api-out store/apiSdk.ts` for typed request hooks

## Quick start

```typescript
import {betterAuthAdapter, bridgeBetterAuthReactClient, createSyncDb} from "@terreno/syncdb";
import {createApiClient} from "@terreno/syncdb/api";
import {createBetterAuthClient, useSession} from "@terreno/syncdb/auth";
import {appHeaders, baseUrl} from "@terreno/syncdb/config";
import {useMutate, useQuery} from "@terreno/syncdb/react";
import {useGetAuthMeQuery} from "@/store/apiSdk";

export const betterAuthClient = createBetterAuthClient({baseURL: baseUrl, scheme: "my-app"});
export const authProvider = betterAuthAdapter(bridgeBetterAuthReactClient(betterAuthClient));

export const syncDb = createSyncDb({authProvider, baseUrl, collections: ["todos"], name: "my-app"});
export const apiClient = createApiClient({
  authProvider,
  baseUrl,
  credentials: "include",
  headers: appHeaders,
});

// Root layout:
// <SessionProvider authClient={betterAuthClient} syncDbs={[syncDb]}>
//   <ApiClientProvider client={apiClient}>
//     <SyncDbProvider client={syncDb}>...</SyncDbProvider>
//   </ApiClientProvider>
// </SessionProvider>

// In a screen:
const {userId, logout} = useSession();
const todos = useQuery<Todo>("todos");
const {create, update, remove} = useMutate("todos");
const {data: me} = useGetAuthMeQuery(); // generated by terreno-syncdb-codegen --api-out
```

## Backend requirements

- `isDeletedPlugin` + `syncPlugin` on each synced schema
- `modelRouter("/path", Model, {sync: {...}, permissions, ...})`
- `SyncApp` + `RealtimeApp` on the Express app
- MongoDB replica set

## Synced vs. request routes

- Synced collections: `useQuery` / `useEntity` / `useMutate` (local-first). Never wrap them in
  request hooks.
- Every other route (`/auth/me`, modelRouter actions, AI, consents, announcements): generated hooks
  in `store/apiSdk.ts` (`useGetAuthMeQuery`, `usePatchAuthMeMutation`, `useLazy…Query`). Regenerate
  with `terreno-syncdb-codegen --schema http://localhost:4000/openapi.json --api-out store/apiSdk.ts`
  (the app's `api-sdk` script) after backend changes. Never edit `apiSdk.ts` by hand.
- Session: `SessionProvider` / `useSession()` from `@terreno/syncdb/auth`.
- Admin: windowed syncdb for String-`_id` models; `AdminProvider`'s fetch client for the rest.

## Local MCP debugging

Create the client with `debug: true`, then use `get_syncdb_state` for debugger
events, status, entities, outbox, conflicts, cursors, streams, and repair
markers. Use `syncdb_snapshot` to capture and compare local state.
`syncdb_action` can mutate/edit, flush, reconcile/resync, resolve/retry, toggle
offline mode, clear events, and merge snapshots when the local MCP starts with
`TERRENO_MCP_EVAL=1`.
