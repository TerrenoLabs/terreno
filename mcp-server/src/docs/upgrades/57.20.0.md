# Upgrading to 57.20.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/rtk, @terreno/ui, @terreno/admin-frontend, @terreno/mcp

## Summary

This release ships the Better Auth account suite: social login, account linking, passkeys,
two-factor with backup codes, closed sign-up, and staff account recovery (`AccountSecurityApp`,
org-admin recovery). It adds drop-in `TerrenoLoginScreen` and `TerrenoAccountSecurityScreen`
screens, `ListDetailLayout`, provisional consent signing, and MCP OAuth client credentials. The
app `User` claim guard now runs before a Better Auth user is created, which can refuse sign-ups
that 57.17.0 accepted. Several defaults also change: the desktop layout floor, sign-out timing,
web autofill, and the hosted MCP URL.

## Breaking changes

### Better Auth claims an existing app `User` only with a verified email or its password

**What changed**

A Better Auth sign-up or sign-in links to an unlinked app `User` with the same email (ignoring
case) only when the provider verified the email, or when the password verifies against that
`User`'s passport-local-mongoose hash. Otherwise the request answers 409 with
`code: "VERIFY_EMAIL_TO_USE_ACCOUNT"` and creates no Better Auth user, account, or verification
email. OAuth callbacks redirect with that `error`. A `User` already bound to another Better Auth
account is refused with `code: "ACCOUNT_ALREADY_EXISTS"`. `syncBetterAuthUser` throws `APIError`
409 instead of inserting a duplicate `User`, and takes a new `password` option.

`BetterAuthApp` registered without a `userModel` now adopts `TerrenoApp`'s user model, and the
`terreno-app-user-sync` plugin syncs the app `User` when each session is created. A
password-proven link that fails to save fails the sign-in with 500 `APP_USER_LINK_FAILED`.

**Why**

57.17.0 checked the claim only after the Better Auth user existed, so a later email verification
could still hand that user someone else's `User`.

**Migration**

Users who sign up with their existing password, or sign in with a provider that verified their
email, link at once. Users with no password hash (for example GitHub JWT sign-in) must reset their
password through JWT `POST /auth/forgotPassword` first, or sign in with a verified provider. Keep
the JWT auth routes mounted while users move. Handle the new 409 codes on your login screen:

```typescript
import {getLoginFeedback} from "@terreno/rtk";

// Before: a generic error for any refused sign-up
setError(error.message);

// After: VERIFY_EMAIL_TO_USE_ACCOUNT reads as "verify your email"
const {notice, error: errorLine} = getLoginFeedback({
  failure: {code: error.code, message: error.message, source: "response"},
  mode: methods?.accountLinking.mode,
});
```

`TerrenoLoginScreen` from `@terreno/rtk` handles these codes for you. See
`docs/explanation/account-linking.md`.

### `accountLinking: {mode: "never"}` refuses `link-social` up front

**What changed**

With linking off (`accountLinking: {mode: "never"}` or
`options.account.accountLinking.enabled: false`), `POST {basePath}/link-social` answers 403
`LINKING_DISABLED` instead of failing at the provider callback.

**Why**

The user learns linking is off before leaving for the provider.

**Migration**

Hide the "Link" action when `useAuthMethods(authClient)` reports linking is off, or treat 403
`LINKING_DISABLED` as a final answer:

```typescript
// Before
await authClient.linkSocial({provider: "google"}); // failed later at the callback

// After
const {methods} = useAuthMethods(authClient);
const canLink = methods?.accountLinking.mode !== "never";
```

### Desktop layout floor moves from 768pt to 1024pt

**What changed**

`Card`, `MarkdownEditor`, the admin shell, and the admin filter drawer use the narrow layout
below 1024pt instead of 768pt. Admin home stacks its panes below that floor.
`ADMIN_FILTER_MOBILE_BREAKPOINT` is now 1024, and `isSupportedDesktopWidth({width})` reports the
floor.

**Why**

Tablets between 768pt and 1023pt got cramped desktop layouts. See
`docs/explanation/responsive-design.md`.

**Migration**

```typescript
// Before
const isDesktop = width >= 768;

// After
import {isSupportedDesktopWidth} from "@terreno/ui";
const isDesktop = isSupportedDesktopWidth({width});
```

Check screens you tuned for 768–1023pt widths, such as iPad portrait.

### `logout()` waits for the server before clearing the session

**What changed**

In `@terreno/rtk` `generateBetterAuthSlice`, `logout()` keeps the session until
`authClient.signOut()` finishes (`signOutTimeoutMs`, default 10 seconds). Meanwhile
`isSigningOut` (`selectBetterAuthIsSigningOut`) is true. A sign-out that fails while the session
is still live stays signed in and sets `error` to `SIGN_OUT_FAILED_MESSAGE`. With `apisToReset`,
the cache purges when the session clears, not at dispatch.

**Why**

A login screen that opened at once could find the still-live session and sign the user straight
back in.

**Migration**

```typescript
// Before: navigate as soon as logout is dispatched
dispatch(betterAuth.actions.logout());
router.replace("/login");

// After: navigate when the session clears; show progress meanwhile
const isSigningOut = useSelector(selectBetterAuthIsSigningOut);
const isAuthenticated = useSelector(selectBetterAuthIsAuthenticated);
```

### `TextField` `autoComplete` now reaches the browser

**What changed**

`TextField` sets `autoComplete` as the input's `autocomplete` attribute on web, and as
`autoComplete` / `textContentType` on native. `autoComplete="off"` now turns autofill off on web.
`LoginScreen` and `SignUpScreen` default email to `"username"`.

**Why**

Password managers could not offer saved credentials or new passwords.

**Migration**

```tsx
// Before
<TextField autoComplete="off" type="email" ... />
<TextField type="password" ... /> // on a set-new-password form

// After
<TextField autoComplete="username" type="email" ... />  // "email" on sign-up
<TextField autoComplete="new-password" type="password" ... />
```

### Hosted Terreno MCP server moves to `https://mcp.terreno.app/mcp`

**What changed**

Docs and `create-terreno-app` now use `https://mcp.terreno.app/mcp`.
`https://mcp.terreno.flourish.health/mcp` keeps serving for at least one more release.

**Why**

The hosted server has a Terreno-owned domain.

**Migration**

```json
// Before (.cursor/mcp.json, .mcp.json)
{"url": "https://mcp.terreno.flourish.health/mcp"}

// After
{"url": "https://mcp.terreno.app/mcp"}
```

Re-run `claude mcp add` registrations with the new URL. See `docs/how-to/set-up-terreno-mcp.md`.

### `SyncStatusBanner` waits before showing Offline

**What changed**

The Offline badge appears only after `isOnline` stays false for `offlineGraceMs` (default 3000 ms).

**Why**

It flashed Offline during the first socket connect and brief drops.

**Migration**

```tsx
// Before: shown immediately
<SyncStatusBanner />

// After: pass 0 to keep the old behavior
<SyncStatusBanner offlineGraceMs={0} />
```

## Deprecations

- `installTerrenoDevConsoleLogger` moves to `@terreno/syncdb` (also
  `@terreno/syncdb/devConsoleLogger`) and takes `{baseUrl}`. The `@terreno/rtk` export is a
  deprecated wrapper that keeps working with no arguments.
- `terreno-mcp-local` `get_rtk_state` is a deprecated alias of the new `get_client_state` for one
  release. It returns the same wrapped response, now with a `layer` field.

## New capabilities

- Better Auth features as config: `accountLinking`, `twoFactor`, `passkey`, `signUp: {mode: "closed"}`,
  `oauthProxy`, `oauthHandoff` linking, and the Sign in with Apple key form. Login screens read
  `GET {basePath}/terreno/methods` through `useAuthMethods`.
- Drop-in screens in `@terreno/rtk`: `TerrenoLoginScreen` (remembered accounts, passkeys, inline
  two-factor) and `TerrenoAccountSecurityScreen`, built on new `@terreno/ui` security cards,
  `OtpField`, `TwoFactorChallengeScreen`, and `FormContainer`.
- `AccountSecurityApp` for staff account recovery under `/users/:id/security`, org-admin recovery
  under `/orgs/:orgId/members/:userId/security`, security notification emails, and
  `UserSecurityScreen` / `MemberSecurityPanel` in `@terreno/admin-frontend`.
- `ListDetailLayout` in `@terreno/ui`, provisional consent signing, and MCP OAuth
  `client_credentials` with loopback redirect ports.

## Verification

- `bun run compile` and `bun run lint` at the app root.
- `cd <your frontend> && bun run sdk` to pick up the new auth and security routes.
- Sign up with an email that matches an existing unverified `User` and confirm a 409
  `VERIFY_EMAIL_TO_USE_ACCOUNT`; sign up with that `User`'s password and confirm it links.
- Sign out on web and confirm the app does not sign back in before the server answers.
- Load key screens at 900pt width and confirm the narrow layout reads well.
