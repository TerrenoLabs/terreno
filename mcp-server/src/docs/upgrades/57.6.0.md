# Upgrading to 57.6.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/test, @terreno/mcp, @terreno/cli, create-terreno-app

## Summary

Bump every `@terreno/*` package together to `57.6.0`. This minor on the Expo SDK 57 line namespaces framework Mongoose models so they no longer collide with consumer `Notification` / `Membership` / `Job` models, moves the GitHub home to `TerrenoLabs/terreno`, and documents TypeScript 6 tsconfig profiles, `@terreno/cli`, Slack member-id mentions, and SyncDB tools on `terreno-mcp-local`. No Expo upgrade is required if you are already on `57.x`.

## Changed behavior

### Framework Mongoose models use `Terreno*` names

**What changed**

Framework-owned models introduced in 57.3 and 57.4 now register as
`TerrenoAuthToken`, `TerrenoMcpServiceToken`, `TerrenoWebhookReceipt`,
`TerrenoInboxNotification`, `TerrenoNotificationPreference`, `TerrenoOrganization`,
`TerrenoMembership`, `TerrenoAuditEvent`, `TerrenoJob`, `TerrenoJobSchedule`, and
the `TerrenoAnnouncement*` names. Public helpers `FRAMEWORK_MODEL_PUBLIC_NAMES` and
`publicFrameworkModelName` map compiled names back to the pre-namespace names used
by admin UI keys and `admin<ModelName>` RBAC resources.

JWT recovery routes also have independent `authOptions` switches:
`passwordReset`, `emailVerification`, and `legacyResetPasswordRoute`. All default on.

**Why**

Generic Mongoose names such as `Notification`, `Membership`, and `Job` collided with
consumer models on the default connection.

**Migration**

No MongoDB migration is needed: every model remains pinned to its existing collection.
Update code that inspects framework `modelName` values. Consumer models can keep their
generic names.

```typescript
// Before: mongoose.model("Notification") could be the framework inbox model
// After: framework inbox is mongoose.model("TerrenoInboxNotification")
// Admin / RBAC still use public names such as "Notification"
```

Set `legacyResetPasswordRoute: false` if your app owns `POST /resetPassword` but still
uses `POST /auth/resetPassword`. See [password-reset.md](../../../docs/how-to/password-reset.md).

### GitHub organization is TerrenoLabs

**What changed**

The repository is `TerrenoLabs/terreno`. The roadmap board is
[github.com/orgs/TerrenoLabs/projects/1](https://github.com/orgs/TerrenoLabs/projects/1).
Package `repository` URLs, docs links, and plugin/skill install commands point at the
new org. Old `FlourishHealth/terreno` URLs redirect.

**Why**

Terreno now lives in its own GitHub organization.

**Migration**

```bash
# Before
/plugin marketplace add FlourishHealth/terreno
npx skills add FlourishHealth/terreno

# After
/plugin marketplace add TerrenoLabs/terreno
npx skills add TerrenoLabs/terreno
```

Update git remotes and clone URLs. Leave the Expo account `flourishhealth` as-is.

### TypeScript 6 tsconfigs

**What changed**

Every Terreno tsconfig builds on TypeScript 6 without `ignoreDeprecations`. Node
packages compile with `module: nodenext` to ES2023 CommonJS so dynamic `import()`
stays a real ESM import (`loadMigrations` can load files by `file://` URL).
Frontend libraries emit ES2022 with bundler resolution and declaration maps.
`@terreno/test` no longer publishes its compiled Bun tests. `create-terreno-app`
scaffolds drop `ignoreDeprecations` and `moduleResolution: node`.

**Why**

TypeScript 6 deprecates options that TypeScript 7 removes. `module: commonjs`
rewrote dynamic `import()` to `require()`, which cannot load `file://` URLs.

**Migration**

If you copied a Terreno tsconfig, drop `ignoreDeprecations` and
`moduleResolution: node`. Use `nodenext` for Node packages and `bundler` for
frontend libraries. See [typescript-configuration.md](../../../docs/explanation/typescript-configuration.md).

Do not import compiled test files from `@terreno/test` — they are no longer in
the published package.

## New capabilities

### `@terreno/cli`

The `terreno` binary searches docs, runs codegen (syncdb, RTK SDK, models, routes,
screens, forms, admin), bootstraps apps, tails unified logs, inspects Redux/RTK
state, and optionally drives CDP / Bun 1.4 WebView proof. OpenAPI helpers:
`terreno api list|call|request` and `generate rest-cli`.

### Slack member-id mentions

`sendToSlack` accepts `mentionUserIds`. Names and emails in the message text do
not notify anyone. Helpers: `formatSlackUserMention`, `normalizeSlackUserId`, and
`lookupSlackUserIdByEmail` (optional `SLACK_BOT_TOKEN` with `users:read.email`).

### SyncDB on `terreno-mcp-local`

Inspect debugger and local-store state, snapshot/compare/merge, mutate entities,
flush the outbox, reconcile/resync, resolve conflicts, retry failures, and
exercise offline transitions. State-changing operations require `TERRENO_MCP_EVAL=1`.
See [debug-with-mcp.md](../../../docs/how-to/debug-with-mcp.md).
