# Upgrading to 57.4.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/ui, @terreno/admin-frontend, @terreno/admin-backend, @terreno/admin-spa, @terreno/announcements, @terreno/jobs, @terreno/mcp, @terreno/syncdb

## Summary

Bump every `@terreno/*` package together to `57.4.0`. This minor on the Expo SDK 57 line adds charts and dashboards, in-app notifications, product announcements, optional organizations, a framework audit log, durable jobs, MongoDB migrations, windowed admin sync, `create-terreno-app`, and first publish of `@terreno/announcements`. Scaffolding moves off the MCP `terreno_bootstrap_app` tool. Admin RTK `useAdminApi` is deprecated for Terreno 58. No Expo upgrade is required if you are already on `57.x`.

## Breaking changes

None

## Deprecations

### `useAdminApi` and the required admin `api` prop

These still work in 57.4.0 and will be removed in Terreno **58**:

- `@terreno/admin-frontend` `useAdminApi` (RTK `injectEndpoints`)
- required `api` prop on admin screens for eligible String-`_id` collections

New admin RPC uses host-bound `adminRequest` / `bindAdminRequest`. Eligible String-`_id` model CRUD uses windowed `@terreno/syncdb` (`AdminProvider` `syncDb`, `sync: {adminBroadcast: true}`). Keep passing `api` only for ObjectId / API-only hosts.

See [migrate-rtk-to-syncdb.md](../../../docs/how-to/migrate-rtk-to-syncdb.md).

## Changed behavior

### Framework Mongoose models use Terreno-specific names

**What changed**

Framework-owned models introduced in 57.3 and 57.4 now register as
`TerrenoAuthToken`, `TerrenoMcpServiceToken`, `TerrenoWebhookReceipt`,
`TerrenoInboxNotification`, `TerrenoNotificationPreference`, `TerrenoOrganization`,
`TerrenoMembership`, `TerrenoAuditEvent`, `TerrenoJob`, `TerrenoJobSchedule`, and
the `TerrenoAnnouncement*` names.

**Why**

Generic Mongoose names such as `Notification`, `Membership`, and `Job` collided with
consumer models on the default connection.

**Migration**

No MongoDB migration is needed: every model remains pinned to its existing collection.
Update code that inspects framework `modelName` values. Consumer models can keep their
generic names.

JWT recovery routes also have independent `authOptions` switches:
`passwordReset`, `emailVerification`, and `legacyResetPasswordRoute`. All default on.
Set `legacyResetPasswordRoute: false` if your app owns `POST /resetPassword` but still
uses `POST /auth/resetPassword`.

### Scaffold with `create-terreno-app`, not MCP `terreno_bootstrap_app`

**What changed**

The MCP tool `terreno_bootstrap_app` is gone. The only supported scaffold is `bunx create-terreno-app` / `npm create terreno-app`. MCP still offers `terreno_bootstrap_ai_rules` for editor rules after the CLI runs.

**Why**

Generated apps need a deployable full-stack tree, not an in-chat file dump.

**Migration**

```bash
# Before
# Call MCP tool terreno_bootstrap_app

# After
bunx create-terreno-app
```

### Admin host auth for native fetch RPC

**What changed**

`AdminProvider` accepts host-injected `credentials` and `getAuthHeaders`. Hosts that inject those use native `adminRequest`. Hosts that pass only `api` keep RTK `injectEndpoints`. The admin SPA uses cookie `same-origin` credentials; the example app sends a Bearer token.

**Migration**

Cookie hosts:

```typescript
<AdminProvider credentials="same-origin" /* ... */>
```

Bearer hosts:

```typescript
<AdminProvider getAuthHeaders={async () => ({Authorization: `Bearer ${token}`})} /* ... */>
```

Hosts that only pass `api` do not need a change in 57.4.0.

### Admin HTTP scripts enqueue `admin/script` when `JobsApp` is registered

**What changed**

Admin panel HTTP script runs enqueue durable job `admin/script` when `JobsApp` is registered. The Scripts UI still polls `BackgroundTask`. If runner enqueue throws, the HTTP handler marks that `BackgroundTask` failed and returns 500. CLI script runs stay in-process.

**Migration**

If you register `JobsApp`, start a worker (`startWorker()`) so admin script runs execute. See [background-jobs.md](../../../docs/how-to/background-jobs.md).

### Combined `terreno-planning` plugin

**What changed**

The plugin now ships Terreno app, docs, upgrade, deployment, and verification skills with the lifecycle. Redundant `commit` and `create-pr` skills are removed in favor of Brew. Several unused Expo skills are no longer distributed. Plugin version is `2.12.0` after Taste re-verify and prepush gates.

**Migration**

Reinstall or update the `terreno-planning` plugin. Use Brew instead of the removed `commit` / `create-pr` skills.

## New capabilities

### Charts and dashboards

`@terreno/ui` ships `LineChart`, `BarChart`, `AreaChart`, `DonutChart`, and `DashboardGrid`. See [charts-and-dashboards.md](../../../docs/how-to/charts-and-dashboards.md).

### In-app notifications

Register `NotificationsApp`. Use `NotificationBell`, `NotificationInbox`, and `NotificationPreferences` from `@terreno/ui`. Inbox mutations use syncdb.

### Product announcements

`bun add @terreno/announcements` and register `AnnouncementsApp`. Frontend: `AnnouncementNavigator`. See [product-announcements.md](../../../docs/how-to/product-announcements.md).

### Optional organizations

Register `OrgsApp` for `Organization` / `Membership`, org context, and org-admin RBAC. Single-tenant apps stay unchanged.

### Audit log

Register `AuditApp` and set `audit: true` on `modelRouter`. See [audit-log.md](../../../docs/how-to/audit-log.md).

### Durable jobs

`@terreno/jobs` `JobsApp` with Mongo, GCP Cloud Tasks, or Vercel Queues runners. See [background-jobs.md](../../../docs/how-to/background-jobs.md).

### MongoDB migrations

`terreno-migrate` plus `TerrenoApp` `migrations.runOnStart`. Production wet apply requires `ALLOW_MIGRATIONS=true`.

### Windowed admin sync

Set `sync: {adminBroadcast: true}` and pass `syncDb` into `AdminProvider`. `GET /admin/config` includes `adminBroadcast` / `syncCollection`.

### `create-terreno-app`

Unscoped CLI published in lockstep. Generated scaffolds pin `^57.4.0` on Terreno dependencies.

### DataTable server-side filtering

Optional `onQueryChange` / `buildDataTableListQuery`. Admin tables adopt the same filter/search UI.

## Verification

- `bun add` every `@terreno/*` dependency to `57.4.0`, then `bun run compile` and `bun run lint` at the app root
- `cd <your frontend> && bun run sdk` after pulling `@terreno/api` (notifications, orgs, audit, migrations, jobs, announcements)
- Replace any `terreno_bootstrap_app` MCP usage with `bunx create-terreno-app`
- If you use admin RPC, inject `credentials` or `getAuthHeaders` (or keep `api` until Terreno 58)
- If you register `JobsApp`, confirm `startWorker()` so admin scripts and enqueued jobs run
- If you enable windowed admin, confirm `adminBroadcast` on the collection and a `Refresh` control on `AdminModelTable`
