# Upgrading to 57.7.0

**Action required:** No
**Affected packages:** @terreno/ui

## Summary

Bump every `@terreno/*` package together to `57.7.0`. `@terreno/ui`'s `Filter` is now `DropdownPanel`. Existing `Filter` and `FilterProps` imports keep working until Terreno 58. Panels stay on screen, render through the `TerrenoProvider` portal on native, and accept styled or custom triggers. No Expo upgrade is required if you are already on `57.x`.

## Breaking changes

None

## Deprecations

### `Filter` and `FilterProps`

**What changed**

`Filter` is renamed to `DropdownPanel`. `Filter` and `FilterProps` stay exported as deprecated aliases and are removed in Terreno 58. `FilterSelectMenu`, `FilterBoolean`, `FilterAccordion`, and `FilterChangesBadge` keep their names.

**Why**

The control is a general compositional dropdown (trigger, anchored panel, optional Apply/Clear/Cancel footer), not a filter-only widget.

**Migration**

```tsx
// Before
import {Filter} from "@terreno/ui";

<Filter label="Status">{children}</Filter>;

// After
import {DropdownPanel} from "@terreno/ui";

<DropdownPanel label="Status">{children}</DropdownPanel>;
```

## Changed behavior

### Panels stay on screen and escape clipping

**What changed**

`DropdownPanel` (including the `Filter` alias) right-aligns to its trigger when a left-aligned panel would cross the right viewport edge, clamps to an 8px screen margin, flips above the trigger when there is no usable room below, and scrolls its body with the footer pinned when the content is taller than the space available. On native it renders through the `TerrenoProvider` portal host, so the panel is no longer clipped inside scroll views or cards. Without a host it stays an inline overlay.

**Why**

Left-aligned panels ran off screen, and inline overlays were clipped by parent scroll views.

**Migration**

No call-site change is required. Pass `align` or `maxPanelHeight` to override the automatic layout. Apps that position their own panels can call `computeDropdownPanelLayout`.

## New capabilities

`DropdownPanel` triggers accept `triggerVariant` (any `Button` variant), `applyButtonVariant`, `triggerSize` on labeled triggers, `fullWidth`, and `renderTrigger` for a fully custom trigger.

## Verification

- `bun add` every `@terreno/*` dependency to `57.7.0`, then `bun run compile` at the app root
- Open a screen that uses `Filter` or `DropdownPanel` and confirm the panel stays inside the viewport, including near the right edge and inside a scrolling parent
- Replace `Filter` imports with `DropdownPanel` before upgrading to Terreno 58
