# Upgrading to 58.1.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/ui

## Summary

A minor release with AI user feedback, `modelRouter` bulk writes, opt-in MCP OAuth grants, a `terreno` CLI that exposes every MCP tool, and a transcript-style `GPTChat`. Three changes need action from some apps: the `GPTChat` test IDs and layout, the MCP OAuth scope handling for `client_credentials`, and the grant model if you switch to `grants`. Apps that do not use `GPTChat` or MCP OAuth only need to bump their `@terreno/*` versions.

## Breaking changes

### GPTChat test IDs and tool rows

**What changed**

`GPTChat` now reads as a transcript. Tool calls are one expandable row, and several test IDs changed or were removed:

- `gpt-copy-image` is removed. Use `gpt-copy-msg-<index>`. It copies the image for an image-only reply and the text when a reply has both.
- Download for an image reply is `gpt-download-image-<index>`.
- Tool rows are labeled `Tool: <name>` instead of `Result: <name>`.
- The **Tools** button (`gpt-tools-button`) appears beside the composer only when `mcpTools` has entries.
- The **Tools** modal hides arguments until **Show arguments** is checked, and it resets to hidden when closed.
- A user or assistant message with no text, content parts, or blocks renders nothing, including its action row.

**Why**

The transcript layout matches how people read long agent replies, and it keeps tool calls from pushing the conversation off screen.

**Migration**

```typescript
// Before
await page.getByTestId("gpt-copy-image").click();
await expect(page.getByText("Result: get_orders")).toBeVisible();

// After
await page.getByTestId("gpt-copy-msg-0").click();
await expect(page.getByText("Tool: get_orders")).toBeVisible();
```

Update any Playwright or Maestro flow that clicks the tools button without `mcpTools` set, because it no longer exists in that state.

### MCP OAuth grants and `registerMCPTool` access

**What changed**

`mcpOAuth.grants` enforces MCP OAuth scopes. The default `mcp` scope is still accepted and is not enforced, so apps that do not set `grants` see no change to tool access. When you do set `grants`, the following apply:

- Every MCP tool is `read` or `write`. CRUD `list` and `read` and GET actions are `read`. Everything else is `write`.
- `registerMCPTool` tools default to `write`. Read-only grants do not see them until you add `access: "read"`.
- Live tokens with the old `mcp` scope match no grant and see no tools. Users reconnect their clients.
- Confidential clients stored with `scope: "mcp"` get `invalid_scope` at `/oauth/token` until their stored scope is updated.
- Bearer-mode web apps add the consent path to `oauthHandoff.callbackPaths`.

**Why**

A read-only MCP client should not be able to change data, and a write-scoped client should be able to say so at consent time.

**Migration**

```typescript
// Before: no grants, every tool is available to any OAuth token
mcpOAuth: {
  consentUrl: "https://app.example.com/oauth/consent",
  enabled: true,
  issuer: "https://api.example.com",
},

// After: read-only clients see read tools, and read/write clients see everything
mcpOAuth: {
  consentUrl: "https://app.example.com/oauth/consent",
  enabled: true,
  grants: "readWrite",
  issuer: "https://api.example.com",
},

// Mark read-only lookups so read-only grants can see them
registerMCPTool({
  access: "read",
  description: "Look up an order by number",
  handler,
  name: "orders_lookup",
  zodSchema,
});
```

Use `"readOnly"` to offer only read access, or pass your own `McpOAuthGrant[]`. Custom scopes cannot contain spaces or repeat.

### `client_credentials` rejects unsupported stored scopes

**What changed**

Even without `grants`, a confidential client whose stored `scope` lists only scopes the server no longer supports now gets `invalid_scope` from `client_credentials`. Before, it received a token. `client_credentials` intersects the stored scope with the supported scopes and answers `invalid_scope` when nothing is left.

**Why**

A token should not carry scopes the server does not enforce.

**Migration**

Update the client's stored `scope` to the scopes your server supports, or leave it unset to receive every supported scope. A client stored with `scope: "mcp"` on an app that uses `grants` needs this change.

## Deprecations

None

## New capabilities

- **@terreno/ai:** end users can rate any AI output. `POST /ai/observability/traces/:id/feedback` records thumbs, an optional comment, and passive signals. `ObservabilityApp({feedbackReview: {evaluatorName}})` queues thumbs-down traces for review. Rejected traces land in datasets as `proofread: false`.
- **@terreno/api:** `modelRouter` takes an opt-in `bulk` option that mounts `POST /<route>/bulk` for up to 100 create, update, and delete operations. By default the batch runs in one MongoDB transaction, which needs a replica set. See `docs/reference/api.md` ("modelRouter bulk writes").
- **@terreno/api:** `validateModelRouterBody` validates one create or update body the way `POST /` and `PATCH /:id` do.
- **@terreno/api:** `createAccess({statementDescriptions})` adds labels to role permissions.
- **@terreno/ui:** `DraggableList` accepts `variableHeight`, and `GPTChat` takes `onRateComment` and `onMessageSignal`.
- **@terreno/syncdb:** `TerrenoOAuthConsentScreen` is a drop-in MCP OAuth consent page.
- **@terreno/cli:** every MCP tool is a `terreno` command, so an agent with a shell needs no MCP configuration.
