# Set up tests in a Terreno app

Apps generated by `create-terreno-app` have `bun test` scripts but no test setup. This guide
adds four layers. Set up the backend first; add the others when you need them.

| Layer | Runs | Tool |
|-------|------|------|
| Backend | routes, models, services against in-memory MongoDB | `bun test` + `@terreno/test` + supertest |
| Frontend unit | components, screens, hooks with React Native mocked | `bun test` + React Native Testing Library |
| Web E2E | the real web app against the real backend | Playwright |
| Mobile | the native app on a simulator or emulator | Maestro |

Agents: the `terreno-test-setup` skill runs these steps; `terreno-backend-tests`,
`terreno-frontend-tests`, and `terreno-mobile-tests` cover writing tests
([install the skills](install-agent-skills.md)).

## Backend

1. Install: `cd backend && bun add -d @terreno/test supertest @types/supertest` (same version
   as `@terreno/api`).
2. `backend/bunfig.toml`:

   ```toml
   [test]
   preload = ["./src/tests/bunSetup.ts"]
   root = "./src"
   ```

3. `backend/src/tests/bunSetup.ts` — register third-party SDK mocks first, then the Mongo
   preload, and reset the mocks before each test:

   ```typescript
   import {registerBackendPreload, registerSendGridMock} from "@terreno/test";

   export const sendGrid = registerSendGridMock();

   registerBackendPreload({
     onBeforeEach: () => sendGrid.reset(),
     testEnv: {tokenIssuer: "my-app.test"},
   });
   ```

4. Write a route test that builds a `TerrenoApp` with `skipListen: true` and only the routers
   under test, then calls it with supertest. Authenticate with
   `authWithToken(app, {token: (await generateTokens(user)).token})`.

The preload starts one `mongodb-memory-server` `mongod` per run (60s launch timeout; the first
run downloads the binary), resets auth env vars, silences logs, and mocks Sentry. It does not
wipe collections: tests delete what they read in `beforeEach`. Code that needs change streams
or transactions sets `process.env.TERRENO_TEST_USE_REPLSET = "true"` at the top of the
preload. Details: [`@terreno/test` reference](../reference/test.md).

## Frontend unit tests

1. Install: `cd frontend && bun add -d @terreno/test @testing-library/react-native@^13
   react-test-renderer@<your react version>`. React Native Testing Library 14 changed `render`
   to async; `renderWithTerreno` targets 13.
2. `frontend/bunfig.toml`:

   ```toml
   [test]
   preload = ["./tests/testPreload.ts"]
   ```

3. `frontend/tests/testPreload.ts`:

   ```typescript
   import {registerExpoTestEnvironment} from "@terreno/test/expo/registerExpoTestEnvironment";

   registerExpoTestEnvironment({expoConfig: {extra: {}, scheme: "my-app"}});
   ```

4. Render components with `renderWithTerreno` from
   `@terreno/test/expo/renderWithTerreno` and select elements by `testID`.

Mock app modules (generated SDK hooks, syncdb hooks) in a second preload file, not in test
files: `mock.module` lasts for the whole test process ([Test isolation](../explanation/test-isolation.md)).

## Web E2E (Playwright)

1. `cd frontend && bun add -d @playwright/test && bunx playwright install --with-deps chromium`
2. Run a replica-set `mongod` (the backend's sync uses change streams).
3. Add `playwright.config.ts` with two `webServer` entries — the backend
   (`bun run --cwd ../backend src/index.ts`, health URL `http://localhost:4000/health`) and
   the web app (`bunx expo start --web --port 8082` with `EXPO_PUBLIC_API_URL`) — a `setup`
   project that creates test users through the auth API, and specs in `e2e/`.
4. Log in with a shared `loginAs(page)` helper in `test.beforeEach`, select by
   `getByTestId`, and wait for each screen's root testID instead of sleeping.

`example-frontend/playwright.config.ts` and `example-frontend/e2e/` in the Terreno repository
are a complete example.

## Mobile (Maestro)

1. Set `ios.bundleIdentifier` and `android.package` in `app.json`.
2. Build a development client on a simulator or emulator: `bunx expo run:ios`,
   `bunx expo run:android`, or an EAS `development` build.
3. On Android, forward Metro and the API: `adb reverse tcp:8081 tcp:8081 && adb reverse tcp:4000 tcp:4000`.
4. Install Maestro (`curl -fsSL "https://get.maestro.mobile.dev" | bash`, Java 17).
5. Write flows in `frontend/maestro/` that select by `id:` (the React Native `testID`) and
   run them: `maestro test -e APP_ID=com.example.myapp maestro/`.

For code that branches on `Platform.OS`, run the unit suite per platform: read the platform
from an env var in `testPreload.ts` (`platform: process.env.TEST_PLATFORM ?? "ios"`) and add
`"test:android": "TEST_PLATFORM=android bun test"`.

## CI

- Unit jobs need only `bun install`; the in-memory `mongod` runs inside the job.
- Large suites: `terreno-test-shard --shard <i>/<n>` splits test files into balanced shards.
- `terreno-test-hygiene --update-baseline` once, then `terreno-test-hygiene` in CI, fails on
  new sleeps, leaked module mocks, and other flaky patterns.
- Playwright and Maestro jobs need a replica-set `mongod` and the backend running; iOS Maestro
  needs a macOS runner.
