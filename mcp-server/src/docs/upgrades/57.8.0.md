# Upgrading to 57.8.0

**Action required:** No
**Affected packages:** @terreno/ui, @terreno/announcements

## Summary

Bump every lockstep `@terreno/*` package together to `57.8.0`. `@terreno/ui` adds opt-in `SplitPage` web layouts and `IconButton` `backgroundOpacity`, and deprecates `isMobileDevice` in favor of `isNarrowViewport` (the old function still returns the same result). `@terreno/announcements` can import a Markdown release pack through `POST /announcements/import-release`. `DropdownPanel` anchors to its trigger, and `/gpt/prompt` emits each generated image once. No Expo upgrade is required if you are already on `57.x`.

## Breaking changes

None

## Deprecations

### `isMobileDevice`

**What changed**

`isMobileDevice` is deprecated. `isNarrowViewport` is the supported name. Both stay exported and return the same boolean: true when the window is below the supported desktop floor (web width under 1024, native width under 1024).

**Why**

`isMobileDevice` described a window-width check. The new name matches that behavior.

**Migration**

```typescript
// Before
import {isMobileDevice} from "@terreno/ui";

if (isMobileDevice()) {
  // narrow layout
}

// After
import {isNarrowViewport} from "@terreno/ui";

if (isNarrowViewport()) {
  // narrow layout
}
```

## New capabilities

`SplitPage` web props are opt-in. Existing callers keep the previous layout.

- `desktopChildrenMinWidth` keeps one or two desktop children at least that many pixels wide and scrolls the row when it is tighter. More than two children keeps the segmented control.
- `narrowViewportChildLabels`, `narrowViewportSelectionActive`, `narrowViewportSelectionKey`, and `narrowViewportListButtonLabel` replace the dotted narrow swiper with a labeled pager.
- `narrowBelowWidth` uses the narrow layout when the window width is less than or equal to that pixel value. Omit it to follow `isNarrowViewport()`.
- Native `SplitPage` ignores these props.
- `IconButton` `backgroundOpacity` tints only that button's background.

`@terreno/announcements` accepts a `terreno.announcement-pack/v1` directory (`pack.yaml` plus one Markdown file per announcement) at `POST /announcements/import-release`. Imports are idempotent by product, release version, channel, and slug, default to drafts, and publish immediately when `publish: true`. Admin auth or bearer `ANNOUNCEMENTS_UPLOAD_TOKEN` can call the route. The token is optional.
