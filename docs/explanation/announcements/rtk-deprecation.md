## `@terreno/rtk` and Redux are removed in Terreno 58

Terreno **58.0.0** deletes `@terreno/rtk` and every Redux dependency. [`@terreno/syncdb`](https://github.com/TerrenoLabs/terreno/blob/master/docs/reference/syncdb.md) is now the only frontend data and session layer. `@terreno/rtk` is not published for 58.

### What changed

- **Collections:** `useQuery` / `useMutate` read and write a local-first store (unchanged since 56).
- **Every other route** (`/auth/me`, modelRouter actions, AI, consents, announcements): a request client in `@terreno/syncdb/api` with typed hooks generated by `terreno-syncdb-codegen --api-out`. Hook names match the old RTK codegen.
- **Session:** `SessionProvider` + `useSession()` from `@terreno/syncdb/auth` (Better Auth, or `jwtAuthAdapter` for JWT backends).
- **Flags and pushes:** ride the syncdb socket (`@terreno/syncdb/flags`, `useSocketEvent`). One socket per app.
- **App utilities:** base URLs in `@terreno/syncdb/config`; upgrade check, permissions, dev logger, and MCP tools in `@terreno/syncdb/app`.
- **Backend:** `GptHistory` and `McpServiceToken` are synced collections with String ids. Two data migrations ship with 58.

### What you need to do

1. Run the `GptHistory` and `McpServiceToken` migrations before deploying 58 frontends.
2. Follow the [upgrade guide](https://github.com/TerrenoLabs/terreno/blob/master/docs/how-to/migrate-rtk-to-syncdb.md). It maps every removed export to its replacement.
3. Remove `@terreno/rtk`, `@reduxjs/toolkit`, `react-redux`, `redux-persist`, and `@rtk-query/codegen-openapi` from the app.

Apps that stay on 57.x keep `@terreno/rtk` 57.x.

### Why

One data layer means one socket, one auth provider, and one cache for every request. See [local-first data](https://github.com/TerrenoLabs/terreno/blob/master/docs/explanation/local-first-data.md).
