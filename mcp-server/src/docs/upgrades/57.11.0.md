# Upgrading to 57.11.0

**Action required:** Yes
**Affected packages:** @terreno/ai, @terreno/api

## Summary

`InProcessRunner` now runs up to eight harness tasks at once. List filters on a field that is not in `queryFields` return 400 before request validation, so that filter can no longer be stripped and ignored. Slack channel helpers and syncdb query windows are opt-in.

## Breaking changes

### InProcessRunner runs tasks in parallel

**What changed**

`new InProcessRunner()` runs up to 8 claimed tasks at once. Each task has its own lease. `stop()` waits for every in-flight task. Turns inside one conversation stay serial. Model calls run in parallel, so provider rate limits, cost, and stream-counter transaction retries all go up.

**Why**

A single slow model call was blocking every other task on that process.

**Migration**

```typescript
// Before: one claimed task at a time
const runner = new InProcessRunner();

// After: keep that behavior
const runner = new InProcessRunner({concurrency: 1});

// Or accept the new default (8)
const runner = new InProcessRunner();
```

### List filters outside queryFields are no longer ignored

**What changed**

`GET` list on `modelRouter` checks every filter against `queryFields` before OpenAPI query validation. A field that is not listed returns 400 `query-param-not-allowed`. The body names the field, the model, and `meta.allowedQueryFields`. `@terreno/syncdb` raises `QueryFieldNotAllowedError` for the same response. Pagination params `limit`, `page`, and `sort` are unchanged.

**Why**

Query validation could strip an unknown filter and still return 200, so the client thought the filter applied.

**Migration**

```typescript
// Before: ?title=ship could be stripped and the list still returned 200
modelRouter("/todos", Todo, {queryFields: ["completed", "ownerId"]});

// After: add the field, or stop sending it
modelRouter("/todos", Todo, {queryFields: ["completed", "ownerId", "title"]});
```

A 400 looks like:

```json
{
  "status": 400,
  "code": "query-param-not-allowed",
  "title": "Query parameter not allowed",
  "meta": {"queryParam": "title", "model": "Todo", "allowedQueryFields": ["completed", "ownerId"]}
}
```

## Deprecations

None

## New capabilities

- `JobsRunner` from `@terreno/ai/harness/jobsRunner` runs each harness phase as a `@terreno/jobs` job (`terreno.harness.phase`) so more than one instance can share the work. `@terreno/jobs` is an optional peer. `HarnessTask.claims` defaults to 0 and needs no migration. See `docs/how-to/run-harness-on-multiple-instances.md`.
- `@terreno/api` Slack helpers use the existing `SLACK_BOT_TOKEN`: `createSlackPrivateChannel`, `inviteSlackUsersToChannel`, `postSlackMessage`, and `findSlackChannelByName`. The bot needs `groups:write`, `groups:write.invites`, `channels:write.invites`, `chat:write`, `channels:read`, and `groups:read`. A taken channel name returns 409.
- `@terreno/syncdb` query windows: set `queryCollections`, then use `client.queryWindows` or `useWindowQuery` (and generated `use{Collection}Window` hooks) for server-filtered, paged lists. `useQuery` and `useEntityIds` accept the same Mongo-style `where`, string sort, and `limit` for local queries. `fullSync: true` adds windows without turning off snapshot sync.

## Verification

- Apps that construct `InProcessRunner` with no options: confirm parallel model calls are acceptable, or pass `{concurrency: 1}`.
- Hit one list route with a filter field that is not in `queryFields` and confirm 400 `query-param-not-allowed` instead of a 200 that ignored the filter.
- `bun run compile` and `bun run lint` at the app root.
