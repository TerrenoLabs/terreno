# Upgrading to 57.12.0

**Action required:** Yes
**Affected packages:** @terreno/ai

## Summary

Harness tasks can record a trace scope, tags, and prompt versions, and `@terreno/ai` publishes official subpath exports. The chat `Project` model registers on first use instead of at import, and harness task HTTP responses no longer include the lease fencing token.

## Breaking changes

### `Project` is no longer registered on import

**What changed**

Importing `@terreno/ai` does not register mongoose model `Project`. The exported `Project` is a lazy proxy. The first property access, `new Project(...)`, or `getProjectModel()` registers the model. Statics and `instanceof Project` still work. These do not:

- `Project === mongoose.models.Project` (and `Project === mongoose.model("Project")`)
- `Object.keys(Project)` (always empty)
- reading `Project.prototype` (throws)

`new AiApp()` still mounts `/gpt/projects` and registers the model when those routes load. `new AiApp({projects: false})` skips those routes.

**Why**

An app that imports `@terreno/ai` and owns its own model named `Project` was hitting a mongoose overwrite error at import time.

**Migration**

```typescript
// Before
import {Project} from "@terreno/ai";

const project = await Project.findExactlyOne({_id: id});
if (mongoose.models.Project === Project) {
  // identity check
}

// After
import {getProjectModel} from "@terreno/ai";

const Project = getProjectModel();
const project = await Project.findExactlyOne({_id: id});
```

To keep a separate app model named `Project`, do not call `getProjectModel()` or touch the `Project` export, and skip the AI project routes:

```typescript
new AiApp({aiService, projects: false});
```

### Harness task HTTP responses omit `lease`

**What changed**

`GET /harness/tasks/:id` no longer includes `lease`. The OpenAPI schema for that response omits it too. Collection list is disabled (`list: []`, 405). The token is still stored on the task document for runners.

**Why**

`lease.token` is the fencing token that decides which runner may commit. It is not a client field.

**Migration**

```typescript
// Before
const token = task.lease?.token;

// After
// Do not read lease from the HTTP task. Runners load it on the server.
```

Regenerate the OpenAPI SDK after upgrading `@terreno/ai` so generated task types drop `lease`.

## Deprecations

`Project` from `@terreno/ai` still works for `find`, `create`, `new`, and `instanceof`. It is deprecated. Call `getProjectModel()` and use that model. A later major can remove the proxy.

## New capabilities

- `harness.createTask(def, input, {trace: {scope, tags}, prompts})` writes a scope (tenant, workspace), tags, and prompt versions onto the task's `ObsTrace`. Child tasks and subagents share that trace. The admin trace list filters with `?scope=`.
- `rt.runAgent` accepts `prompts` and a registry `PromptVersionRef` as `instructions`. It runs `body` and records the version on the trace.
- Subpath exports: `@terreno/ai/admin`, `@terreno/ai/harness/agentLoop`, `@terreno/ai/harness/commit`, `@terreno/ai/harness/events`, `@terreno/ai/harness/internalRuntime`, `@terreno/ai/observability/observabilityApp`, `@terreno/ai/observability/localPlugin`, `@terreno/ai/observability/promptStore`.

## Verification

- Code that imported `Project` from `@terreno/ai`: switch identity checks and `mongoose.models.Project` reads to `getProjectModel()`.
- An app that owns a model named `Project`: pass `projects: false` and do not call `getProjectModel()`.
- Harness clients: confirm `GET /harness/tasks/:id` JSON has no `lease`, then regenerate the SDK.
- `bun run compile` and `bun run lint` at the app root.
