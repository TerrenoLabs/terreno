# Upgrading to 58.2.0

**Action required:** No
**Affected packages:** @terreno/api, @terreno/ui, @terreno/admin-spa

## Summary

A minor release. MCP OAuth can accept Claude's published client identity (Client ID Metadata Documents), serve its own password and authenticator-code consent page, and limit who may approve a connection. `@terreno/admin-spa` ships its web export again, so `AdminSpaServeApp` serves `/console` from the published package. The default `primary500` and the primary `Button` fill are darker. Apps that do not use MCP OAuth only need to bump their `@terreno/*` versions and check any screenshot tests that show primary buttons.

## Breaking changes

None

## Visual changes

### Primary button fill

**What changed**

`@terreno/ui` default `primary500` is `#0C80A7`. Primary `Button` fills use the new `surface.primaryDark` (`#0C80A7` in light mode, `#40B8E0` in dark mode). Dark-mode `border.ai` follows `primary500`. `IconButton`, `Slider` and `DataTable` still use `surface.primary`.

**Why**

The lighter fill gave white button text too little contrast.

**Migration**

No code change. Custom themes may omit `surface.primaryDark`: theme resolution copies `surface.primary` into it. Update visual snapshots that include primary buttons.

```typescript
// Optional: set it explicitly in a custom theme
const theme = {surface: {primary: "#0E9DCD", primaryDark: "#0C80A7"}};
```

## Deprecations

None

## New capabilities

- `mcpOAuth.clientIdMetadataDocuments.allowedClientIds`: accept allowlisted Client ID Metadata Documents, such as `https://claude.ai/oauth/mcp-oauth-client-metadata`, so a Claude.ai connector can use "Use Claude's published identity" with no client to create first.
- `mcpOAuth.consent.mode: "builtin"`: a consent page at `/oauth/consent/:request` that asks for email, password and an authenticator code on every approval. It needs a `BetterAuthApp` with `twoFactor`.
- `mcpOAuth.consent.requireAdmin` and `requireTwoFactor`: limit who may approve a connection.
- `@terreno/admin-spa` includes `dist/`, so `AdminSpaServeApp` no longer needs a locally built `ADMIN_SPA_DIST_DIR`.

## Verification

- `bun run compile` and `bun run lint` at the app root
- With MCP OAuth: `curl -s <api>/.well-known/oauth-authorization-server | jq .client_id_metadata_document_supported` prints `true` once `allowedClientIds` is set
- With `AdminSpaServeApp`: `curl -s -o /dev/null -w '%{http_code}' <api>/console/login` returns `200`, not `503`
