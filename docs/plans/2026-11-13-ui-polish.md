# Make @terreno/ui look designed out of the box

An app built on `@terreno/ui` today shows two typefaces on its first screen: headings and body
text use the theme fonts, while button labels, field labels, helper text and banners fall back to
the browser's system font. The warning colour fails contrast, a boxy opaque shadow dates every
card, the data table breaks on a phone, and about 75 colours are written into components where a
theme cannot reach them. This plan fixes the look and the phone-width behaviour of the components
that already exist, so an unstyled Terreno app looks designed and can be re-themed in one place.
Every adopter sees the change on upgrade, so the plan also records how the new defaults ship and
how to get the old ones back.

Source: audit `docs/audits/2026-11-12/` findings 5.7, 5.8, 5.9, 5.10 (`REPORT.md`) and
`ui-ux.md` H1, H2, H3, H6, H8, Q5, Q6, Q7. Prop-name aliases, `testID` and RadioField coverage
are in the sibling plan `docs/plans/2026-11-13-ui-api-consistency.md`.

## The idea

- **One typeface.** A single exported helper maps a weight to the loaded theme font name. Every
  component that renders text uses it. A source guard stops new raw `Text` without a font.
- **Readable warning.** The light theme's `surface.warning` moves to the darker `warning200`.
- **Themeable colours and a soft shadow.** New theme tokens (`surface.overlay`, an `elevation`
  group, badge border tokens) replace literals in Badge, SelectBadge, Avatar, Modal, sheets,
  pickers and the toast container. `Box shadow` reads `theme.elevation.default`, a soft two-layer
  shadow. A ratchet test stops new literals.
- **Phone width.** `useNarrowViewport()` re-renders on resize and rotation. BooleanField, the
  login account chip and DataTable stop overflowing at 375 px.
- **Compatibility.** The new look is the default, with no feature flag. The shadow, the warning
  fill and the table stripe are theme tokens, and the upgrade note gives the one-line override
  that restores each. The typeface change has no way back: button and field text simply stop
  falling back to the system font. New theme keys are optional in the config types, so a
  hand-written theme keeps compiling. Rejected: an opt-in "new look" flag, because the point is
  the look a new app gets without configuration.

Proof for layout and computed fonts needs a real browser, which the ui package has only for its
one-path smoke. The first task adds browser specs on the same demo export, sharing one harness
with the `ui-accessibility` plan (see Dependencies).

## Tasks

Shared rules for every task:

- Unit tests use `renderWithTheme` from `@terreno/ui` (`ui/src/test-utils` export) and run with
  `bun test --only-failures <path>` from `ui/`.
- Browser specs run with `bun run compile && bun run --cwd demo export && bun run --cwd ui test:e2e`.
  They select by `testID` only and never call `waitForTimeout`.
- A task that changes committed `__snapshots__` files regenerates only the snapshots of the test
  files it touches (`bun test --update-snapshots <path>`), and lists in its commit body what
  changed in them (font family, colour, shadow) so a reviewer can tell intended churn from a
  regression.
- Reference docs, the upgrade note and changelog fragments are written once, in T16 (see
  Assumption A1). Roast does not fail T2–T15 for missing reference docs; it fails T16.
- Unit tests that depend on the web layout branch set `Platform.OS = "web"` for the test and
  restore it after (the ui test setup defaults to `"ios"`, where `isNative()` is true).
- Test skills for every task: `terreno:terreno-frontend-tests`; UI tasks also `terreno:terreno-ui`.
