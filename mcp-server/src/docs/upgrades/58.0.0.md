# Upgrading to 58.0.0

**Action required:** Yes
**Affected packages:** @terreno/ui, @terreno/rtk, @terreno/syncdb, @terreno/admin-frontend, @terreno/api, create-terreno-app

## Summary

First release of the Expo SDK 58 line. Upgrade the app to Expo 58 and React Native 0.88, rebuild native binaries, then bump every `@terreno/*` package to `58.0.0` together. This major also removes the APIs deprecated during 57.x; each removal has its own section below.

## Upgrade Expo before Terreno

| Package | Version |
|---------|---------|
| `expo` | `~58.0.14` |
| `react-native` | `0.88.0` |
| `react` / `react-dom` | `19.3.0` |
| `@types/react` | `~19.3.0` |
| `@sentry/react-native` | `~8.28.0` (major 7 → 8) |
| `react-native-gesture-handler` | `~3.3.0` (major 2 → 3) |
| `react-native-webview` | `14.0.1` (major 13 → 14) |

Run `bunx expo install expo@^58.0.0 --fix` at the app root, rebuild dev clients and store binaries (the native fingerprint changes), then `bun run compile` / `bun run lint`.

### Expo Router `initialRouteName`

**What changed**

Expo Router 58 no longer accepts `initialRouteName` as a `<Slot>` / `<Stack>` / `<Navigator>` prop. `SidebarNavigation` ignores it.

**Migration**

```tsx
// Before
<Slot initialRouteName="home" />

// After — in the same _layout.tsx
export const unstable_settings = {initialRouteName: "home"};
<Slot />
```

### Custom `app/+html.tsx`

Expo Router 58 renders static web pages by streaming. The bundle `<script>` tags,
React Native Web styles, and route metadata now reach a custom `app/+html.tsx` through
`useServerDocumentContext()`. A `+html.tsx` that does not render them exports pages with
no JavaScript: the static HTML shows, but nothing hydrates or responds.

```tsx
import {ScrollViewStyleReset, useServerDocumentContext} from "expo-router/html";

export default function Root({children}: {children: React.ReactNode}) {
  const {bodyAttributes, bodyNodes, headNodes, htmlAttributes} = useServerDocumentContext();
  return (
    <html lang="en" {...htmlAttributes}>
      <head>
        <meta charSet="utf-8" />
        <ScrollViewStyleReset />
        {headNodes}
      </head>
      <body {...bodyAttributes}>
        {children}
        {bodyNodes}
      </body>
    </html>
  );
}
```

Apps without a custom `+html.tsx` need no change.

### React Native 0.88 instance types

**What changed**

React Native 0.87+ ships generated types without `react-native-legacy-deep-imports`. Component names such as `View`, `Text`, `ScrollView`, and `TextInput` are no longer usable as ref types. `Box.scrollRef`, `TextField.inputRef`, and the `Text` `ref` now use the instance types.

**Migration**

```tsx
// Before
const ref = useRef<TextInput>(null);

// After
import type {TextInputInstance} from "react-native";
const ref = useRef<TextInputInstance>(null);
```

Use `ViewInstance`, `TextInstance`, `ScrollViewInstance`, and `TextInputInstance`. `TextStyle` is `Readonly`; build style objects instead of mutating them. `TextInput.State.currentlyFocusedInput()` replaces `currentlyFocusedField()`.

### `@terreno/ui` peer dependency

`@terreno/ui` peers `react-native` `0.88.0`. Installing `@terreno/ui@58` next to Expo 57 is unsupported.

### `@sentry/react-native` 8

Expo 58 bundles `@sentry/react-native` `~8.28.0`. Follow Sentry's 7 → 8 migration guide for your app's `Sentry.init` options.

## `Filter` and `FilterProps` are removed

`@terreno/ui` removes the `Filter` and `FilterProps` aliases added as deprecations in 57.7.0. Import `DropdownPanel` and `DropdownPanelProps`. `FilterSelectMenu`, `FilterBoolean`, `FilterAccordion`, and `FilterChangesBadge` keep their names. See [57.7.0](57.7.0.md).

## HTTP rate limiting defaults on

`TerrenoApp` will enable HTTP rate limiting by default (memory store unless you pass `store`). Apps that must stay unlimited must pass an explicit off once 58 defines that API.

Until 58: omit `rateLimit` to leave the limiter off. See [Rate limiting](../../../docs/how-to/rate-limiting.md).

## Legacy RTK realtime is removed

Terreno 58 deletes the RTK cache-patching realtime path. Collection live updates go through `@terreno/syncdb`: `sync` on `modelRouter` plus `sync:delta` events. `RealtimeApp` stays: it still hosts Socket.io, socket auth, change streams, and `sync:delta`. `SyncApp`, `admin.realtime` (`admin:model.changed` events), `useSocketConnection`, and `useRealtimeDebug` are unchanged.

Removed from `@terreno/api`:

- `modelRouter` option `realtime`. Passing it is now a TypeScript error.
- The `sync` websocket event. The change stream emits only `sync:delta` for models registered with `sync`.
- The `subscribe:model`, `subscribe:document`, and `subscribe:query` socket events (and their `unsubscribe:*` pairs, plus `query:subscribed`).
- Types `RealtimeConfig`, `RealtimeEvent`, `DocumentSubscription`, and `QuerySubscription`.
- Registry helpers `registerRealtime`, `getRealtimeRegistry`, `findRegistryEntryByCollection`, `findRegistryEntryByRoutePath`, `updateRealtimeRegistryOptions`, `clearRealtimeRegistry`, and type `RealtimeRegistryEntry`.
- Query store helpers `addQuerySubscription`, `removeQuerySubscription`, `removeAllSocketQueries`, `getQuerySubscriptionsForCollection`, `computeQueryId`, and `clearQueryStore`.
- Constants `MAX_MODEL_SUBSCRIPTIONS`, `MAX_DOCUMENT_SUBSCRIPTIONS`, and `MAX_QUERY_SUBSCRIPTIONS`.

Removed from `@terreno/rtk`:

- `realtimeList`, `realtimeDocument`, `setRealtimeSocket`, `getRealtimeSocket`, `useSyncConnection`, and type `RealtimeEvent`.

To upgrade:

1. Backend: delete `realtime: {...}` from every `modelRouter` config. For each collection that needs live updates, add `syncPlugin` + `isDeletedPlugin` to the schema and a `sync` config to the router (three-argument form), then register `SyncApp` next to `RealtimeApp`.
2. Frontend: delete `setRealtimeSocket(socket)`, `useSyncConnection(...)`, and every `onCacheEntryAdded: realtimeList(...)` / `realtimeDocument(...)` override. Read and write synced collections with `useQuery` / `useMutate` from `@terreno/syncdb/react`.
3. Tests: replace `clearRealtimeRegistry()` with `clearSyncRegistry()`, which clears the whole collection catalog.

See [Migrate from @terreno/rtk to @terreno/syncdb](../../../docs/how-to/migrate-rtk-to-syncdb.md).
