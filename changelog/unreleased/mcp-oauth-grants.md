category: Added

- **@terreno/api:** `mcpOAuth.grants` enforces MCP OAuth scopes. Pass `"readOnly"` (`mcp:read`), `"readWrite"` (`mcp:read`, `mcp:write`), or your own `McpOAuthGrant[]` (`{scope, label, description?, access: "read" | "write"}`). Every MCP tool is `read` or `write` (CRUD `list`/`read` and GET actions are `read`; the rest are `write`), and an OAuth token sees and can call only the tools its grants allow. Write implies read. `MCPConfig.scopes`, an action's `mcp.scope`, and `registerMCPTool({access, scope})` tag tools; `canUseMcpTool` and `MCP_OAUTH_GRANT_PRESETS` are exported. Without `grants`, nothing changes.
- **@terreno/api:** `POST /oauth/authorize/:request/approve` accepts an optional `{scope}` so the user can approve a subset of the requested scopes, and `GET /oauth/authorize/:request` returns `grants` with each grant's label and description. `client_credentials` now intersects a client's stored scope with the supported scopes and answers `invalid_scope` when nothing is left.
- **@terreno/syncdb:** `TerrenoOAuthConsentScreen` is a drop-in MCP OAuth consent page: `TerrenoLoginScreen` inline while signed out, then the client, redirect host, a checkbox per grant, and Approve and Deny. `useMcpOAuthConsent` is the hook behind it. `TerrenoLoginScreen` and `useLoginController` take `methods` to show only some of the server's sign-in methods.
- **Upgrade:** switching an app with connected clients from the default `mcp` scope to `grants` ends access for live `mcp`-scoped tokens (users reconnect), and confidential clients stored with `scope: "mcp"` get `invalid_scope` at `/oauth/token` until their stored scope is updated. Custom tools from `registerMCPTool` default to `write`, so add `access: "read"` to read-only tools or read-only grants will not see them. Bearer-mode web apps add the consent path to `oauthHandoff.callbackPaths`. See [Enable MCP OAuth](docs/how-to/enable-mcp-oauth.md).
- **Behavior change, even without `grants`:** a confidential client whose stored `scope` lists only scopes the server no longer supports now gets `invalid_scope` from `client_credentials`, where it used to get a token. Update the client's `scope`, or leave it unset to receive every supported scope.
