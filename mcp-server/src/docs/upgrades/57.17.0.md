# Upgrading to 57.17.0

**Action required:** Yes
**Affected packages:** @terreno/api, @terreno/admin-backend, create-terreno-app

## Summary

This release hardens authentication and RBAC from an internal security audit, adds bearer-mode
Better Auth for web apps on another site (with an OAuth handoff for social sign-in), opt-in MCP
OAuth for JWT apps, and one token source for `@terreno/rtk`. Three changes need action: email
changes on `PATCH /auth/me` require the current password, permission sources fail closed when
their deny posture is unknown, and RBAC identity writes on other users need a new permission.

## Breaking changes

### `PATCH /auth/me` requires `currentPassword` to change the email

**What changed**

A body that changes the email to a different mailbox must include `currentPassword`. A missing
or wrong password gets 403 and nothing is saved. A user with no password (for example
GitHub-only) gets 400 and must set one through the reset flow first. Casing-only changes and an
unchanged email echoed back need no password. After a change, the previous address gets a
notice through `authOptions.sendMail`.

**Why**

A stolen session alone could move the account to a new mailbox and then take it over with a
password reset.

**Migration**

```typescript
// Before
await patchMe({email: newEmail}).unwrap();

// After: collect the current password in the profile form when the email changes
await patchMe({email: newEmail, currentPassword}).unwrap();
```

Apps that use `setupServer` with Better Auth and no `TerrenoApp` pass
`authOptions.verifyBetterAuthPassword` (see `verifyBetterAuthCredentialPassword`). See
`docs/reference/api.md#changing-the-email-on-patch-authme`.

### `PermissionSource.failClosedWhenDenyUnknown` defaults to `true`

**What changed**

When a source's `getGrants` fails for a user this process has no last-known deny posture for,
permission checks throw 503 `Permission source unavailable` instead of resolving local roles
without the source's `deny`.

**Why**

Granting local roles while a source that can deny is unreachable could let a denied user through.

**Migration**

```typescript
// Sources that never return `deny` can keep the old outage behavior
const source: PermissionSource = {
  name: "myAdditiveRoles",
  failClosedWhenDenyUnknown: false,
  getGrants: async ({user}) => ({roles: ["viewer"]}),
};
```

The built-in organization membership source already sets it. See
`docs/reference/api.md#rbac-permission-sources`.

### RBAC writes to another user's identity fields need `user:updateIdentity`

**What changed**

With `accessControl`, changing another user's `email`, `disabled`, `betterAuthId`, `githubId`,
or `emailVerified` requires `user:updateIdentity` in addition to `user:update`, across
modelRouter, sync, MCP, instance actions, and AdminApp `PATCH` and bulk-patch. Writes without it
get 403 `Missing user:updateIdentity permission`. Newly seeded `admin` roles include it;
`superadmin` gets it through `*`. Legacy `admin: true` users and self-writes are unaffected.

**Why**

`user:update` alone let operators take over accounts by changing their email or auth links.

**Migration**

`seedDefaults` does not update an `admin` role that is already stored. Add `updateIdentity` to
that role's `user` actions once per deployment:

```typescript
// Before: the stored admin role has user: ["create", "list", "read", "update"]
// After: read the role, add the action, and send the role's full permissions back
const {data: roles} = await (await fetch(`${api}/rbac/roles`, {headers})).json();
const role = roles.find((r) => r.name === "admin");
const permissions = {...role.permissions, user: [...role.permissions.user, "updateIdentity"]};
await fetch(`${api}/rbac/roles/admin`, {
  body: JSON.stringify({permissions}),
  headers: {...headers, "Content-Type": "application/json"},
  method: "PATCH",
});
```

`permissions` replaces the role's whole permission set, so always send every statement back. See
`docs/reference/api.md#rbac-user-identity-writes`.

## Deprecations

None

## New capabilities

- `createBetterAuthClient({webAuth: "bearer"})`, `BetterAuthConfig.oauthHandoff`,
  `signInSocialWithHandoff`, and `completeBetterAuthOAuthHandoff` for web apps whose frontend
  and API are on different sites.
- `TerrenoApp` `mcpOAuth: {enabled: true}` and modelRouter action `mcp: {name}` tools.
- `setTokenSource` in `@terreno/rtk`, read by `emptySplitApi`, `useSocketConnection`,
  `useTerrenoChat`, `useMCPTools`, and `createOfflineMiddleware`.
- `BetterAuthConfig` `options` and `plugins`, and `WhatsNewBanner` in `@terreno/ui`.

- Change the email on the profile screen with and without the current password and confirm 403
  without it and success with it
- With RBAC, the `admin` role from `GET /rbac/roles` lists `updateIdentity` under `user`
- `cd <your frontend> && bun run sdk` after upgrading `@terreno/api`
