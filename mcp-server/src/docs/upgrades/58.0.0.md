# Upgrading to 58.0.0

**Action required:** Yes
**Affected packages:** @terreno/ui, @terreno/rtk, @terreno/syncdb, @terreno/admin-frontend, @terreno/api, create-terreno-app

## Summary

First release of the Expo SDK 58 line. Upgrade the app to Expo 58 and React Native 0.88, rebuild native binaries, then bump every `@terreno/*` package to `58.0.0` together. This major also removes the APIs deprecated during 57.x; each removal has its own section below.

## Upgrade Expo before Terreno

| Package | Version |
|---------|---------|
| `expo` | `~58.0.14` |
| `react-native` | `0.88.0` |
| `react` / `react-dom` | `19.3.0` |
| `@types/react` | `~19.3.0` |
| `@sentry/react-native` | `~8.28.0` (major 7 → 8) |
| `react-native-gesture-handler` | `~3.3.0` (major 2 → 3) |
| `react-native-webview` | `14.0.1` (major 13 → 14) |

Run `bunx expo install expo@^58.0.0 --fix` at the app root, rebuild dev clients and store binaries (the native fingerprint changes), then `bun run compile` / `bun run lint`.

### Expo Router `initialRouteName`

**What changed**

Expo Router 58 no longer accepts `initialRouteName` as a `<Slot>` / `<Stack>` / `<Navigator>` prop. `SidebarNavigation` ignores it.

**Migration**

```tsx
// Before
<Slot initialRouteName="home" />

// After — in the same _layout.tsx
export const unstable_settings = {initialRouteName: "home"};
<Slot />
```

### Custom `app/+html.tsx`

Expo Router 58 renders static web pages by streaming. The bundle `<script>` tags,
React Native Web styles, and route metadata now reach a custom `app/+html.tsx` through
`useServerDocumentContext()`. A `+html.tsx` that does not render them exports pages with
no JavaScript: the static HTML shows, but nothing hydrates or responds.

```tsx
import {ScrollViewStyleReset, useServerDocumentContext} from "expo-router/html";

export default function Root({children}: {children: React.ReactNode}) {
  const {bodyAttributes, bodyNodes, headNodes, htmlAttributes} = useServerDocumentContext();
  return (
    <html lang="en" {...htmlAttributes}>
      <head>
        <meta charSet="utf-8" />
        <ScrollViewStyleReset />
        {headNodes}
      </head>
      <body {...bodyAttributes}>
        {children}
        {bodyNodes}
      </body>
    </html>
  );
}
```

Apps without a custom `+html.tsx` need no change.

### React Native 0.88 instance types

**What changed**

React Native 0.87+ ships generated types without `react-native-legacy-deep-imports`. Component names such as `View`, `Text`, `ScrollView`, and `TextInput` are no longer usable as ref types. `Box.scrollRef`, `TextField.inputRef`, and the `Text` `ref` now use the instance types.

**Migration**

```tsx
// Before
const ref = useRef<TextInput>(null);

// After
import type {TextInputInstance} from "react-native";
const ref = useRef<TextInputInstance>(null);
```

Use `ViewInstance`, `TextInstance`, `ScrollViewInstance`, and `TextInputInstance`. `TextStyle` is `Readonly`; build style objects instead of mutating them. `TextInput.State.currentlyFocusedInput()` replaces `currentlyFocusedField()`.

### `@terreno/ui` peer dependency

`@terreno/ui` peers `react-native` `0.88.0`. Installing `@terreno/ui@58` next to Expo 57 is unsupported.

### `@sentry/react-native` 8

Expo 58 bundles `@sentry/react-native` `~8.28.0`. Follow Sentry's 7 → 8 migration guide for your app's `Sentry.init` options.

## `Filter` and `FilterProps` are removed

`@terreno/ui` removes the `Filter` and `FilterProps` aliases added as deprecations in 57.7.0. Import `DropdownPanel` and `DropdownPanelProps`. `FilterSelectMenu`, `FilterBoolean`, `FilterAccordion`, and `FilterChangesBadge` keep their names. See [57.7.0](57.7.0.md).

## HTTP rate limiting defaults on

`TerrenoApp` will enable HTTP rate limiting by default (memory store unless you pass `store`). Apps that must stay unlimited must pass an explicit off once 58 defines that API.

Until 58: omit `rateLimit` to leave the limiter off. See [Rate limiting](../../../docs/how-to/rate-limiting.md).

## New native modules (rebuild dev clients)

Terreno 58 adds every native module the B2B features need in one release, so later features ship as JavaScript and OTA updates against the same binary. A dev client or store build made before 58 does not contain these modules. Apps that call them on an old binary crash or get `null` modules.

| Package | Version | Config plugin |
| --- | --- | --- |
| `@stripe/stripe-react-native` | `0.81.0` | Yes: `merchantIdentifier`, `enableGooglePay` |
| `react-native-purchases` | `10.12.2` | None |
| `react-native-purchases-ui` | `10.12.2` | None (keep the same version as `react-native-purchases`) |
| `expo-device` | `~58.0.5` | None |
| `expo-crypto` | `~58.0.2` (unchanged pin) | None |
| `expo-local-authentication` | `~58.0.2` | Yes: `faceIDPermission` |
| `expo-system-ui` | `~58.0.6` | Applied automatically |
| `expo-build-properties` | `~58.0.11` | Yes: Android Kotlin and `compileSdkVersion` pins |

`react-native-otp-verify` is not in the baseline. It does not support the New Architecture, the only architecture React Native 0.88 runs. For one-time codes, use `TextInput` with `textContentType="oneTimeCode"` (iOS) and `autoComplete="sms-otp"` (Android), which need no native module.

Checklist:

1. Add the packages to the app with `bunx expo install @stripe/stripe-react-native react-native-purchases@10.12.2 react-native-purchases-ui@10.12.2 expo-device expo-crypto expo-local-authentication expo-system-ui expo-build-properties`. In the Terreno monorepo they are root catalog entries; reference them with `"catalog:"`.
2. Add the config plugins to `app.json` (or `app.config.ts`). Replace the merchant id with your own Apple Pay merchant id; register it in the Apple Developer portal before the iOS build.

   ```json
   [
     "expo-build-properties",
     {"android": {"compileSdkVersion": 37, "kotlinVersion": "2.2.21"}}
   ],
   [
     "@stripe/stripe-react-native",
     {"enableGooglePay": true, "merchantIdentifier": "merchant.com.yourcompany.app"}
   ],
   [
     "expo-local-authentication",
     {"faceIDPermission": "Allow $(PRODUCT_NAME) to use Face ID to confirm it is you."}
   ]
   ```

   React Native 0.88 already compiles against Android SDK 37. Stripe needs at least SDK 36 and Kotlin 2.x; the pins keep both explicit. Kotlin `2.2.21` matches the Stripe Android build default and Expo's KSP table.
3. Rebuild every dev client and store binary (`eas build --profile development` for iOS and Android). Expo fingerprints change, so OTA updates from 57 binaries do not apply to 58 binaries.
4. Open the demo's hidden **Native Modules** page (`/demo/Native%20Modules`) on the new dev client. Each native module must show **Linked**. Web shows **Native only**.

What still works in Expo Go:

| Flow | Expo Go |
| --- | --- |
| `expo-device`, `expo-crypto`, `expo-system-ui` | Works (bundled in Expo Go) |
| `expo-local-authentication` | Works, except Face ID on iOS (Expo Go has no Face ID usage string); use a dev build |
| `react-native-purchases` / `-ui` | Runs in RevenueCat Preview API mode: mock offerings and paywalls, no real purchases |
| `@stripe/stripe-react-native` | Card flows work (Expo Go 58 bundles `0.81.0`). Apple Pay and Google Pay need a dev build, because the merchant id is set by the config plugin |
| Web | Unchanged. Native-only calls need a `Platform.OS` guard |
