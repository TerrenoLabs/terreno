# Upgrading to 57.22.0

**Action required:** Yes
**Affected packages:** @terreno/ai

## Summary

`@terreno/ai` drops its Langfuse integration. The built-in observability registry replaces it: `ObservabilityApp` with `createLocalObservabilityPlugin()` provides prompts, traces, and the review queue. `addGptRoutes` reads its system prompt from that registry. This release also adds review batches with LLM judge agreement, shared prompt references (`{{> name}}`), and a seed that fills every AI Observability screen. Apps that never imported Langfuse exports have nothing to change.

## Breaking changes

### Langfuse exports are removed from `@terreno/ai`

**What changed**

These exports are gone: `LangfuseApp`, `LangfuseCache`, `getCached`, `setCached`, `invalidateCache`, `initLangfuseClient`, `getLangfuseClient`, `isLangfuseInitialized`, `shutdownLangfuseClient`, `compilePrompt`, `createPrompt`, `getPrompt`, `invalidatePromptCache`, `initTracing`, `shutdownTracing`, `createTelemetryConfig`, and `preparePromptForAI`. The types `ChatMessage`, `GetPromptOptions`, `LangfuseAppOptions`, `LangfuseCachedPrompt`, `PaginatedResult`, `PreparePromptResult`, `PromptListItem`, `ScoreSubmission`, `ScoringFunction`, `TelemetrySettings`, and `TraceListItem` are gone too. The `@terreno/ai/langfuseApp` and `@terreno/ai/langfuseClient` subpaths no longer exist. `@terreno/ai` no longer depends on `@langfuse/client`, `@langfuse/otel`, or `@opentelemetry/*`. `ControlPrimary` is now only `"local"`.

**Why**

The built-in observability registry covers prompts, traces, and review. Two systems of record for the same prompts drifted apart.

**Migration**

Register the local observability plugin and read prompts from its registry:

```typescript
// Before
import {LangfuseApp, getPrompt} from "@terreno/ai";
app.register(new LangfuseApp({...}));
const prompt = await getPrompt("summarize");

// After
import {createLocalObservabilityPlugin, getObservabilityApp, ObservabilityApp} from "@terreno/ai";
app.register(new ObservabilityApp({plugins: [createLocalObservabilityPlugin()]}));
const prompt = await getObservabilityApp()?.promptRegistry?.get({label: "production", name: "summarize"});
```

Recreate any Langfuse prompts in the registry (the AI Observability prompt hub in the admin panel). Then remove the Langfuse packages from the app if nothing else uses them.

### `addGptRoutes` drops `langfuseSystemPromptName`

**What changed**

`langfuseSystemPromptName` is removed. Chat turns no longer set `experimental_telemetry`.

**Why**

The system prompt now comes from the observability registry, and its version is recorded on the trace.

**Migration**

```typescript
// Before
addGptRoutes(router, {aiService, langfuseSystemPromptName: "chat-assistant"});

// After
addGptRoutes(router, {aiService, systemPromptName: "chat-assistant", systemPromptLabel: "production"});
```

### Langfuse environment variables and secrets

**What changed**

The example backend no longer reads `LANGFUSE_SECRET_KEY`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_BASE_URL`, `LANGFUSE_ORGANIZATION`, `LANGFUSE_PROJECT`, or `LANGFUSE_PROJECT_ID`. The Terreno deploy scripts stop mounting the Langfuse secrets. `infra/flourish/main.tf` drops the two Langfuse Secret Manager modules.

**Why**

Nothing reads them any more.

**Migration**

Deploy a revision without the Langfuse secret mounts first, then run `terraform apply` (it deletes `backend_secret_langfuse_secret_key` and `backend_secret_langfuse_public_key`). Applying first breaks the running revision's secret mounts.

## Deprecations

None

## New capabilities

- `addGptRoutes` options `systemPromptName` and `systemPromptLabel` prepend a registry prompt to the chat system prompt.
- Registry prompts can include other prompts with `{{> base-rules}}`, `{{> base-rules label=staging}}`, or `{{> base-rules version=3}}`. A reference that doesn't resolve, or that creates a cycle, is rejected with 400 when the prompt is saved.
- Review batches (`POST /ai/observability/review/batches`) and LLM judge runs over a batch with agreement scores (`POST /ai/observability/review/batches/:id/judgeRuns`).
- `bun run backend:seed`, or the `seedAiObservabilityDemo` admin script, fills every AI Observability screen with demo data.

## Verification

- `rg -n "langfuse|Langfuse" --glob '!**/node_modules/**' src` in the backend returns nothing.
- `bun run compile` and `bun run lint` pass at the app root.
- A chat turn through `/gpt/prompt` creates a trace that lists the registry system prompt version.
