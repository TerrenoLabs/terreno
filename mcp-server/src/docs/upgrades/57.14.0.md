# Upgrading to 57.14.0

**Action required:** No
**Affected packages:** @terreno/syncdb

## Summary

`@terreno/syncdb` pages snapshot streams in parallel (up to 6 at once by default) instead of one at a time, so cold start, reconcile, subscribe catch-up, `forceResync`, and wipe re-bootstrap finish faster when an app has many collections or scopes. Each stream now runs one snapshot pass at a time, which stops a concurrent pass from marking a purged stream bootstrapped over rows it never paged. No code change is required.

None

## New capabilities

### `snapshotConcurrency` on `createSyncDb`

The client now sends up to `snapshotConcurrency` snapshot requests at once (default `DEFAULT_SNAPSHOT_CONCURRENCY`, 6). If your backend cannot take the extra parallel load at cold start, lower it. `1` restores the old one-stream-at-a-time behavior.

```typescript
// Before
export const syncDb = createSyncDb({authProvider, baseUrl, collections, name: "my-app"});

// After (only if you need to limit parallel snapshot requests)
export const syncDb = createSyncDb({
  authProvider,
  baseUrl,
  collections,
  name: "my-app",
  snapshotConcurrency: 2,
});
```

A new how-to, `docs/how-to/use-syncdb-correctly.md`, lists library behavior apps have to handle.
